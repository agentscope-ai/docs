---
title: "概述"
description: "让智能体直接听用户说话并用语音回答，可随时打断，并在对话中调用工具"
---

当开发者需要让智能体直接"听"用户说话并用语音回答时，可以使用实时语音智能体。它把语音输入、回合判断、打断、工具调用与语音输出串成一条持续运行的对话流，开发者只需要接上音频来源并消费事件。

实时语音智能体有两种实现方式，区别在于语音与语言模型之间如何衔接：

| 实现 | 工作方式 | 特点 | 状态 |
|------|----------|------|------|
| 全双工（Speech-to-Speech） | 音频直接进出一个实时语音模型，由模型 API 维护会话 | 延迟低，保留语气与情绪；可选模型较少，上下文按轮数限制 | 已提供，见[全双工语音智能体](/versions/2.0.8dev/zh/building-blocks/realtime/full-duplex) |
| 级联（ASR + LLM + TTS） | 语音识别转成文字交给 `Agent`，回复再由语音合成播放 | 可复用任意文字模型与现有智能体的全部能力；延迟略高 | 即将支持 |

两种实现共用同一套智能体能力，目前在全双工版本中已经实现：

| 能力 | 说明 |
|------|------|
| 全双工语音对话 | 麦克风音频持续上行，模型音频持续下行，没有请求与回复的边界 |
| 回合检测 | 默认由模型 API 判断用户何时说完，也可以传入本地 VAD（语音活动检测）自行判断 |
| 打断 | 用户开口即打断当前回复，上下文中只保留用户实际听到的部分；也可以由代码主动打断 |
| 工具调用与用户确认 | 复用 `Toolkit` 与权限系统，需要确认的工具调用会在语音流不停的情况下发出确认事件 |
| 文本输入 | 在支持文本输入的模型上，可以在语音对话中直接发送文字 |
| 断线恢复 | 模型 API 因长时间空闲关闭会话后，下一句话自动重连，对话历史保留在 `agent.state` 中 |
| 回合整理 | 合并被停顿切开的句子，过滤"嗯""好的"等没有实际内容的应答 |
| 延迟指标 | 每一轮对话记录端点检测、模型首包、播放链路三段延迟 |

<Warning>
实时语音智能体目前为实验性功能，接口在后续版本中可能调整。
</Warning>
