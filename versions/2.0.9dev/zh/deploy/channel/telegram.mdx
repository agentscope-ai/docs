---
title: "Telegram"
description: "通过 Telegram 机器人与 AgentScope 服务中的智能体对话。"
---

Telegram 渠道通过长轮询将 AgentScope 服务接入 Telegram Bot API，无需公网回调地址，支持私聊、群聊、多模态消息、流式回复和聊天内工具审批。

目前支持以下能力：

- **流式回复**：私聊使用 Telegram 草稿，群聊按照平台允许的频率更新普通消息；
- **多模态输入**：接收照片、相册、文档、音频、语音、视频、动画、视频便笺、贴纸、位置、地点和联系人；
- **格式化输出**：将常用 Markdown 转换为 Telegram 安全的 HTML，并自动拆分长回复；
- **交互式审批**：需要确认的工具调用通过“允许”和“拒绝”按钮处理；
- **主动发送**：智能体可以向已知 Telegram 聊天 ID 发送文字、图片和文件。

## 前置条件

Telegram 渠道依赖 `python-telegram-bot` 和 `markdown-it-py`，通过 `channel` 可选依赖安装：

```bash 安装依赖
pip install "agentscope[channel]"
```

## 创建机器人

通过 [BotFather](https://t.me/BotFather) 创建并配置机器人。

<Steps>
  <Step title="创建机器人">
    向 BotFather 发送 `/newbot`，按提示设置显示名称和用户名。
  </Step>
  <Step title="记录令牌与机器人 ID">
    复制 BotFather 返回的令牌。冒号前的数字是机器人 ID。完整令牌属于敏感凭据，请妥善保管。
  </Step>
  <Step title="配置群聊权限">
    使用 BotFather 的群组和隐私设置，控制机器人能否加入群聊及 Telegram 会向它投递哪些群消息。开启隐私模式后，命令、提及和对机器人的回复仍可被接收。
  </Step>
  <Step title="关闭 Webhook">
    AgentScope 使用 `getUpdates` 长轮询。同一机器人启用渠道前不能保留 Webhook。
  </Step>
</Steps>

## 启动智能体服务

Telegram 渠道运行在[智能体服务](/versions/2.0.9dev/zh/deploy/agent-service)中。通过 `create_app` 注册 `TelegramChannel`：

```python 启动支持 Telegram 的服务
from agentscope.app import create_app
from agentscope.app.channel import TelegramChannel
from agentscope.app.message_bus import InMemoryMessageBus
from agentscope.app.storage import RedisStorage
from agentscope.app.workspace_manager import LocalWorkspaceManager

app = create_app(
    storage=RedisStorage(host="localhost", port=6379),
    # 多进程部署请改用 RedisMessageBus。
    message_bus=InMemoryMessageBus(),
    workspace_manager=LocalWorkspaceManager(basedir="./workspaces"),
    channels=[TelegramChannel],
)
```

多进程或多节点部署必须使用 `RedisMessageBus`。Telegram 渠道通过共享消息总线选出唯一的长轮询监听者，并在不同进程间关联审批回调；监听租约失效后，备用工作进程会接管。

## 添加渠道

在管理界面添加 Telegram 渠道，也可以直接调用 `/channels` 接口。

<Steps>
  <Step title="选择 Telegram">
    新建渠道，并把平台类型设为“Telegram”。
  </Step>
  <Step title="填写凭据">
    输入从 BotFather 获得的数字格式 **Bot ID** 和完整 **Bot Token**。
  </Step>
  <Step title="配置路由">
    选择处理消息的智能体，以及聊天与会话的映射方式。详见[会话路由](/versions/2.0.9dev/zh/deploy/channel/routing)。
  </Step>
  <Step title="保存并启用">
    保存并启用渠道。长轮询启动后，渠道状态会变为已连接。
  </Step>
</Steps>

## 平台配置

Telegram 渠道提供以下平台专属字段：

| 字段 | 说明 | 默认值 |
|---|---|---|
| `only_at_reply` | 在群聊和超级群组中，仅在机器人被提及或用户回复机器人消息时响应 | `true` |
| `show_thinking` | 在回复中显示模型的思考过程 | `false` |
| `show_tool_process` | 在回复中显示工具调用和执行结果 | `false` |

<Note>
按 `chat_type` 路由时，私聊使用 `private`，群聊使用 `group` 或 `supergroup`。
</Note>

<Warning>
知道机器人用户名的用户都可以访问 Telegram 机器人，本渠道没有单独的用户或群聊白名单。配置路由和工具权限时，应按公开入口进行安全设计。在群聊中，审批消息对所有成员可见，同一聊天中的任何非机器人用户都能点击审批按钮。
</Warning>

## 消息限制

Telegram 渠道按以下方式处理平台限制：

| 内容 | 处理方式 |
|---|---|
| 文本 | 转换为安全 HTML，并拆分为最长 4,096 个字符的消息 |
| 入站附件 | 在 Bot API 的 20 MiB 限制内下载 |
| 出站图片 | 不超过 10 MiB 时以内嵌图片发送 |
| 出站文件 | 不超过 50 MiB 时以文档发送 |
| 流量限制 | 在单次操作的有限重试预算内重试 |

## 智能体工具

Telegram 渠道提供以下工具，每个工具执行前都需要用户确认：

| 工具 | 作用 |
|---|---|
| `SendMessage` | 向 Telegram 聊天 ID 发送纯文本 |
| `SendImage` | 内嵌发送工作区中的图片 |
| `SendFile` | 以文档形式发送工作区中的文件 |

Telegram 没有提供枚举机器人全部聊天或成员的完整接口，因此本渠道不提供聊天列表和成员列表工具。

## 验证与排查

- 在管理界面或通过 `GET /channels/{id}/status` 查看连接状态。
- 如果机器人无法连接，确认机器人 ID 与令牌匹配，并检查令牌是否已撤销。
- 如果服务提示存在活动 Webhook，请先删除 Webhook，再重新启用渠道。
- 如果机器人忽略群聊消息，请提及机器人或回复它的消息，也可以关闭 `only_at_reply`。
- 如果 Telegram 提示存在另一个 `getUpdates` 消费者，请停止竞争的轮询程序。AgentScope 会重试冲突，并通过共享消息总线协调自身副本。
- 如果媒体收发失败，请检查上表中的大小限制以及 Telegram 是否支持该文件格式。
